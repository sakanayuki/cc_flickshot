# どうぶつの やまのぼり

昔の駄菓子屋にあった「10円ゲーム機」のWebアプリ版です。
コインを弾いて山のてっぺんのゴールを目指します。**3歳児が一人でも遊べること**を最優先に作っています。

遊ぶ: https://sakanayuki.github.io/cc_flickshot/

## ⚠️ 公開するのに1回だけ必要な手動設定

リポジトリの **Settings → Pages → Build and deployment → Source** を
**「GitHub Actions」** に変更してください。

これをしないと、ワークフローは成功するのにページが公開されません。
設定後、`main` へ push すれば自動でデプロイされます。

## 遊びかた

1. タイトルで「やさしい」か「ふつう」を選ぶ
2. コインが投入されて、いちばん下の坂に転がり出てくる
3. **画面右下の赤いノブを下に引っ張って、指を離す**と、5段すべてのレバーが同時に動いてコインを弾き上げる
4. 引いた長さが弾く力になる。強すぎても失敗にはならない
5. 途中の穴に落ちるか、山頂のゴールに入るか、「やめる」を1秒長押しすると結果画面へ
6. ゴールするとどうぶつのスタンプがもらえる(端末に保存されるので次回も残る)

3歳児向けの配慮:

- 指を動かす距離を **450px** と長く取ってあり、多少ズレても届く(成功域はストロークの 73%)
- ドラッグが横に蛇行しても、縦の移動量だけを見るので影響しない
- 「やめる」は誤タップで発動しないよう **1秒長押し**。指がずれたらキャンセル
- 2秒何もしないと、指のアイコンが引っ張る動きを見せる(ひらがなが読めなくても分かる)
- 失敗しても責める演出はしない。穴に落ちても「おしい!」

## 開発

```bash
npm install
npm run dev       # 開発サーバ
npm test          # 物理・判定のユニットテスト
npm run verify    # 盤面の幾何と「遊べるか」の検算
npm run build     # 本番ビルド
```

### `npm run verify` について

このゲームは盤面の座標と物理定数が噛み合っていないと簡単に遊べなくなります。
実際に開発中、次のような不具合が起きました。

- 弾き角が浅く、コインが次の段の先端を越える前にシャフトの天井に当たって戻され、成功域がストロークの **2%** しかなくなった
- 落下閾値の設定ミスで、**一度も弾く前に**コインが穴に落ちるようになった
- 転落の閾値が低く、ほどほどの強さで弾くたびに毎回1段下へ落ちるようになった

いずれも座標の計算は正しいのに遊べない、という種類の不具合です。
`npm run verify` は**実際の物理を回して**これらを検出します。
`src/config.ts` の数値を変えたら必ず実行してください(CI でも実行しています)。

### 構成

```
src/
  config.ts          全チューニング定数と共有型
  main.ts            起動・シーンマシン・メインループ
  save.ts            スタンプの永続化(localStorage が使えなくても動く)
  game/              Canvas も DOM も触らない純粋なゲームロジック
    board.ts         レーン・穴・ゴールの幾何
    coin.ts          コインの状態機械と物理
    plunger.ts       プランジャーの入力
    levers.ts        レバーの連動
  render/            描画のみ
    layout.ts        720x1280 論理座標 → 実画面(DPR 対応)
    shapes.ts        描画プリミティブ
    animals.ts       どうぶつ10種
    drawings.ts      盤面・筐体・UI
    particles.ts     紙吹雪
  scenes/            タイトル / ゲーム / リザルト
scripts/
  verify-geometry.ts 幾何と遊びやすさの検算
docs/
  detailed-design.md 詳細設計書
```

`game/` は Canvas も DOM も参照しないので、物理をヘッドレスでテストできます。

### 技術的な制約

- **外部素材ゼロ**。画像・音・フォント・CDN を一切使わず、すべて Canvas 2D のコード描画
- **ランタイム依存ゼロ**(devDependencies のみ)
- 音は鳴りません(仕様)
- 物理は自作。物理エンジンは使いません(3歳児向けに予測可能な挙動を作り込むため)
