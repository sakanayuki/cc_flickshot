# どうぶつの やまくだり

昔の駄菓子屋にあった「10円ゲーム機」のWebアプリ版です。
コインを弾いて上から下へ降ろし、いちばん下の「あたりの口」を目指します。
**3歳児が一人でも遊べること**を最優先に作っています。

遊ぶ: https://sakanayuki.github.io/cc_flickshot/

## ⚠️ 公開するのに1回だけ必要な手動設定

リポジトリの **Settings → Pages → Build and deployment → Source** を
**「GitHub Actions」** に変更してください。

これをしないと、ワークフローは成功するのにページが公開されません。
設定後、`main` へ push すれば自動でデプロイされます。

## 遊びかた

盤面には**1本につながったレーン(溝)**が引かれています。長い直線を走り、
壁でUターンして1段下へ、を繰り返しながら下りていきます。
レーンには丸い落とし穴が開いていて、走路の端(画面の左右の端)には
コインを受け止める**止まり木**と、その横の壁から生えた**レバー**があります。

```
        ←───────────────●   走路1。右上から入って左へ走る
       ╭╯
   ○○───────────────→●     走路2。●=止まり木(横の壁にレバー)
                     ╰╮      ○=落とし穴(アウト)
   ●←───────────────○○
```

1. タイトルで「やさしい」か「ふつう」を選ぶ
2. **画面右上の投入口**からコインが入り、レーンを走って1つ目の止まり木で止まる
3. **画面右下の赤いノブを下に引っ張って、指を離す**と、5つすべてのレバーが
   同時にはたき、止まり木のコインを送り出す
4. **コインは飛びません。勢いがついてレーンの上を走ります。**
   走りながら摩擦で少しずつ遅くなっていきます
5. 引いた長さが走る勢いになる
   - ちょうどよい強さ → 穴を勢いよく渡りきり、**次の止まり木で止まる**
   - 弱すぎ → 穴を渡りきれずに落ちてコイン没収
   - 強すぎ → 止まり木を乗り越えてしまい、**その先の穴**に落ちて没収
6. 5回弾いて、レーンの終点の**「あたりの口」**に入れられたらクリア
7. 穴に落ちるか、あたりに入るか、「やめる」を1秒長押しすると結果画面へ
8. あたりを出すとどうぶつのスタンプがもらえる(端末に保存されるので次回も残る)

3歳児向けの配慮:

- コインは必ず止まり木で止まるので、**急かされない**。落ち着いて狙える
- 難易度は**穴の長さだけ**で変えている。止まり木の位置もレーンの形も動かないので、
  指の感覚は「やさしい」でも「ふつう」でも同じ
- 「やさしい」は引き量の **65%** が成功する(「ふつう」は 48%)
- ドラッグが横に蛇行しても、縦の移動量だけを見るので影響しない
- 「やめる」は誤タップで発動しないよう **1秒長押し**。指がずれたらキャンセル
- 2秒何もしないと、指のアイコンが引っ張る動きを見せる(ひらがなが読めなくても分かる)
- 失敗しても責める演出はしない。穴に落ちても「おしい!」

## 開発

```bash
npm install
npm run dev       # 開発サーバ
npm test          # 物理・判定のユニットテスト
npm run verify    # 盤面の幾何と「遊べるか」の検算
npm run build     # 本番ビルド
```

### `npm run verify` について

このゲームは盤面の座標と物理定数が噛み合っていないと簡単に遊べなくなります。
実際に開発中、次のような不具合が起きました。

- **コインが棒を貫通した。** コインを放物線で飛ばしていた頃、弾道が自分の乗っている
  棒の内部を通っていた(いまはレーンに沿った1次元運動なので原理的に起きない)
- 板の幅を 10px 広げただけで板が壁に接し、**「強すぎ」の失敗が消滅**して片側だけのゲームになった
- 弾き力の上限が高すぎて、ストロークの上半分が丸ごと「強すぎ」になり成功域が半減した
- 座標の計算は正しいのに、実際に物理を回すとコインが一度も弾く前に穴へ落ちた
- コインがレーンの途中で完全に止まってしまい、弾くこともできず**詰んだ**

いずれも「計算は合っているのに遊べない」種類の不具合です。
`npm run verify` は**実際の物理を回して**これらを検出します。とくに

- 成功域が**連続した1区間**であること(飛び地がないこと)
- どの遷移でも**弱すぎ・強すぎの両方で落ちる**こと
- 5回の操作が**すべて完全に同じ条件**であること(距離を実測して突き合わせる)
- 全パワーを掃引して、コインが**必ず決着する**(途中で止まって詰まない)こと

の4つは、ルールそのものが壊れていないかを守っています。
`src/config.ts` の数値を変えたら必ず実行してください(CI でも実行しています)。

### 構成

```
src/
  config.ts          全チューニング定数と共有型
  main.ts            起動・シーンマシン・メインループ
  save.ts            スタンプの永続化(localStorage が使えなくても動く)
  game/              Canvas も DOM も触らない純粋なゲームロジック
    board.ts         棒(板)・丸穴・あたりの口の幾何
    coin.ts          コインの状態機械と物理(サブステップ+実体衝突)
    plunger.ts       プランジャーの入力
    levers.ts        レバーの連動
  render/            描画のみ
    layout.ts        720x1280 論理座標 → 実画面(DPR 対応)
    shapes.ts        描画プリミティブ
    animals.ts       どうぶつ10種
    drawings.ts      盤面・筐体・UI
    particles.ts     紙吹雪・土煙・星
  scenes/            タイトル / ゲーム / リザルト
scripts/
  verify-geometry.ts 幾何と遊びやすさの検算
docs/
  detailed-design.md 詳細設計書
```

`game/` は Canvas も DOM も参照しないので、物理をヘッドレスでテストできます。

### 技術的な制約

- **外部素材ゼロ**。画像・音・フォント・CDN を一切使わず、すべて Canvas 2D のコード描画
- **ランタイム依存ゼロ**(devDependencies のみ)
- 音は鳴りません(仕様)
- 物理は自作。物理エンジンは使いません(3歳児向けに予測可能な挙動を作り込むため)
- 空中のコインは**1サブステップ 6px 以下に分割して積分**し、すべての棒と
  実体(上面・厚み・端面)で衝突します。どんな速度でも貫通しません
- 壁でも棒の端でも**跳ね返らせません**。跳ね返ると「強すぎたのに壁のおかげで助かる」が起きて、
  *強すぎ = 失敗* というルールが壊れるためです
