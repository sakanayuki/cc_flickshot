# どうぶつの やまくだり

昔の駄菓子屋にあった 10 円ゲーム機(エレメカ筐体)の Web 版。
コインを弾いてななめ上向きのレーンを登らせ、**ちょうどいい落とし穴に落として**
5 段おりていく。強すぎても弱すぎても手前・奥のポケットで止まって終わり。
**下の段ほど穴が遠く、狭くなる。**

物理は **Matter.js**。盤面は静的剛体として組んであり、落とし穴は単に床が無い区間。
落ちるか渡りきるかを判定する特別なルールは持たず、剛体シミュレーションが決める。

- 公開 URL: <https://sakanayuki.github.io/cc_flickshot/>
- 仕様: [`plan.md`](plan.md) が**唯一の仕様書**

## 遊びかた

1. タイトル画面で難易度(**やさしい / ほんき**)を選ぶ。
2. 右上の投入口からメダルが入り、1 段目のレールを滑って壁ぎわのレバーで止まる。
3. **右下のプランジャーを下へ引いて離す**と、全段のレバーが同時にコインを蹴る。
4. コインはレーンを登り、レールの端から先の窪みに落ちる。
   窪みは底から立つ薄いフィン 2 枚で 3 つに分かれていて、まん中だけ底が無い。

   | 落ちた場所 | 結果 |
   |---|---|
   | 手前のポケット | **弱すぎ**。コイン没収 |
   | 落とし穴 | **ちょうど**。1 段下のレーンへ進む |
   | 奥のポケット | **強すぎ**。コイン没収 |

5. これを 5 回。最後の落とし穴はあたりの口につながっている。

コインは必ずレバーで止まるので**時間制限は無い**。

### 下の段ほど難しい

段が下るごとに、落とし穴が**遠く・狭く**なり、フィンが**深く**なる。
同じ引き方を 5 回使い回すことはできない。

| 成功する引き量の幅 | 段1 | 段2 | 段3 | 段4 | 段5 |
|---|---|---|---|---|---|
| やさしい | 60% | 48% | 41% | 30% | **20%** |
| ほんき | 43% | 35% | 29% | 21% | **14%** |

難易度が変えるのは**弾く力の上限だけ**で、盤面は共通。
上限が広いほど同じ指の動きで力が大きく変わる = レバーが敏感になる。

### パワーメーター

操作部の左のメーターには**直前 8 発ぶんのショットの跡**が、引き量の位置に色で残る。

- 黄 = よわい / 青緑 = ちょうど / 赤 = つよい

成功する範囲そのものは表示しない。自分が撃った跡だけを見て詰めていく。

## 開発

```bash
npm ci
npm run dev       # 開発サーバ
npm run verify    # 盤面の検算(Matter.js を実際に回して成功域を測る)
npm test          # ユニットテスト
npm run build     # 型チェック + 本番ビルド
```

`npm run verify` と `npm test` は **CI(デプロイ)の前段でも走る**。
`src/config.ts` の数値を変えたら必ず両方を通すこと。

### 技術的な制約

- **重力は画面の下向き。** レーンの上の減速は `g・sinθ` として自然に出る。
- **摩擦は 0。** Matter の摩擦は低速で速度をまるごと消す近似が入っていて、
  0.02 でも実測 2700 px/s² という減速になる。
- **コインは物理では回さない。** 円は多角形なので、回すと平らな床で上下に振動し、
  レール端を離れる瞬間の速度がばらついて結果が単調でなくなる。見た目の回転は描画側で作る。
- **跳ね返らせない**(反発係数 0)。跳ねると「強すぎたのに助かる」が起きてルールが崩れる。
- **上を向いた面を飛行経路のきわに置かない。** 角にかすったコインは中心が角より
  上にあるぶん必ず上へ弾かれ、下向きの速さを失って滑空し、受け皿を 1 つ飛び越す。
  「弱く弾いたほうが遠くに入る」飛び地になる。上を向いているのは幅 8px の
  フィンの頂点だけにし、それもレール面よりはっきり下に置く。
- **ポケットの底は傾けない。** レーン自体が傾いているので、落ちたコインは
  自然に穴から遠ざかる向きへ滑って止まる。傾けると穴に近い側の角が持ち上がり、
  それが飛行経路に入って上の壊れ方をする。
- **2 枚のフィンは同じ深さにする。** 奥だけ深くすると、手前のフィンの頂点に
  着地して落下がリセットされたコインが奥のフィンを越えてしまい、飛び地ができる。
- 1 フレームを 5 回に分けて Matter に渡し、高速のコインがレールの角をすり抜けないようにする。
- 更新は固定タイムステップ(60Hz、accumulator 方式)、描画は `requestAnimationFrame`。
- **毎フレーム走る描画に `shadowBlur` と全画面グラデーションを足さない。**
  重さは JavaScript ではなくラスタライズ側にある(JS は 1 フレーム 2.6ms しか
  使っていないのに 8fps しか出ていなかった)。動かないものは `render/layer.ts` で
  1 枚に焼き、全画面の合成は 1 フレームにつき 1 回に抑える。

理由の詳細は [`plan.md` §4.1 / §4.2 / §4.5](plan.md) にまとめてある。数値を触る前に必ず読むこと。

### 盤面の数値を変えるとき

手で当たりを付けようとしないこと(角に当たったときの挙動が式に乗らない)。

```
npx tsx scripts/search.ts   # 候補を総当たりで物理にかけ、良い順に並べる
npx tsx scripts/probe.ts    # いまの盤面の段ごとの成功域を掃引する
npx tsx scripts/trace.ts <力> <段>   # 1 発ぶんの軌跡を出す
```

どれも CI には入れない。本番の検算は `npm run verify`。

## デプロイ

`main` への push で GitHub Actions が
`npm run verify` → `npm test` → `npm run build` を通してから GitHub Pages へ公開する。

リポジトリ側で **Settings → Pages → Source を「GitHub Actions」にする**手動設定が 1 度だけ必要。
